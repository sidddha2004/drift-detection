# Pre-registered Analysis Plan

| | |
|---|---|
| **Status** | v1.0, written before any Phase 3+ experiment was run (Phase 1 baselines are frozen at tag `phase1-frozen`) |
| **Rule** | Anything below may only change through a dated entry in the "Amendments" section, made *before* the affected experiment is run. Deviations found later are reported as such in the paper. |

## 1. Confirmatory hypotheses

| ID | Hypothesis | Primary comparison |
|---|---|---|
| H1 | The proposed system (E8) recovers post-drift accuracy better than passive federated learning with local fine-tuning. | E8 vs **E3b (FedAvg + local fine-tune)** |
| H2 | Drift-triggered adaptation beats a drift-unaware schedule at equal or lower communication. | E8 vs E3 (FedAvg) and vs E3c (FedAvg + periodic retraining) |
| H3 | E8 is competitive with or better than published federated-drift methods under our protocol. | E8 vs the best E7 method (chosen on the *validation* schedule) |
| H4 | Adapter-only adaptation is non-inferior to full retraining on macro-F1 and uses substantially fewer uplink bytes. | Non-inferiority margin **1.0 macro-F1 point**; bandwidth claim only if uplink reduction is **> 70%** |
| H5 | Choosing the response by drift type beats one fixed response for all drifts. | Typed policy vs best fixed policy (always full retrain / fine-tune / adapter) |

H1–H3 and H5 are tested per drift scenario S1, S2, S3. S0 (no drift) is used only for false alarms and overhead.

## 2. Primary endpoint

**Post-change macro-F1**: for each drifted client, the mean macro-F1 over all evaluation rounds from the ground-truth change point to the end of the stream, evaluated on that client's held-out *post-drift* windows. It is averaged over drifted clients to give one number per (method, scenario, seed).

Reported alongside, never instead: mean over **all** clients, **worst-client** macro-F1 and accuracy.

## 3. Secondary endpoints (descriptive, no confirmatory claim)

- Detection: mean detection delay (windows and rounds), missed events, false-alarm rate on S0 (alarms per 1,000 windows).
- Adaptation: recovery time (rounds to regain 95% of the pre-drift macro-F1), maximum accuracy drop, area under the recovery curve, backward retention on pre-drift windows (S3).
- Communication: uplink + downlink payload bytes per round and cumulative.
- Compute: local training time, detector latency per window, peak memory.
- Clustering (only if the extension is built): cluster-size histogram, ARI against ground-truth drift groups.
- Drift typing: 4-class accuracy and confusion matrix on real model-error streams.

## 4. Experimental design (fixed)

- **Data protocol, split, budget:** exactly as Phase 1 (`configs/phase1_baselines.yaml`, tag `phase1-frozen`): 8 clients (subjects 101-108), correct ±16g channels, blocked split for the stationary control, locked budget (FedAvg 60 rounds x 2 local epochs, 120 epochs for centralised/local).
- **Seeds:** the 5 frozen seeds `42, 123, 999, 2024, 7` plus 5 new ones `11, 13, 17, 19, 23` = **10 seeds** for all headline comparisons. Each seed fixes model initialisation, batch order and the drift schedule realisation.
- **Tuning data:** hyperparameters of every method (including baselines, with equal tuning effort) are tuned on a **separate validation drift schedule** built with seeds `1001-1003`, never on the evaluation schedules.
- **Baselines:** E1, E2, E3, E3b, E3c, E4, E5, E6, E7 (list fixed at the start of Phase 6), E8. Re-implementations use the same backbone and budget; differences from the original papers are documented.
- **Checkpoint selection:** by validation macro-F1 only; test windows are never used for selection.
- **Exclusions:** no run or seed may be dropped after seeing results. A crashed run is re-run with the same seed; any other exclusion needs an amendment.

## 5. Statistics

- Unit of analysis: **seed** (one value per method x scenario x seed, after averaging over clients). Clients within a seed are not treated as independent replicates.
- Per comparison: mean paired difference, 95% bootstrap CI (10,000 resamples), and a paired two-sided **Wilcoxon signed-rank** test. With 10 seeds the smallest attainable p is 0.002.
- **Multiplicity:** the confirmatory family is H1, H2, H3, H5 x scenarios S1-S3 (up to 12 tests); **Holm-Bonferroni** correction over the family. Significance threshold 0.05 after correction.
- **Non-inferiority (H4):** the 95% bootstrap CI of (full retrain − adapter) macro-F1 must lie entirely below +1.0 point.
- Effect sizes are reported for every comparison; a result is only called "significant" if both the corrected p < 0.05 and the CI excludes 0.
- All numbers in the paper are generated by scripts in `experiments/` from JSON files in `results/`, each carrying the git commit and full config.

## 6. Reporting commitments

- Negative and null results are reported (e.g. if typing does not beat a fixed response, if clustering does not help, if E8 does not beat E3b).
- The natural-drift probe (temporal split) is presented as a **secondary sanity check only**. Phase 1b showed that most of its gap to the blocked split is a bout-edge effect, not distribution drift (see `docs/decisions.md`).
- Privacy claims are limited to data locality unless Phase 6b is run.

## Amendments

### Amendment A1 - 2026-10-27 (before any Phase 2+ experiment; before the v2 baseline re-run)
- **Data protocol v2:** a 5 s (500-sample) trim is cut from both ends of every bout before windowing (`trim_samples: 500`, `configs/phase1_v2_trimmed.yaml`). Rest of the protocol (split, budget, seeds, channels) is unchanged from Section 4.
- **Justification (fixed before seeing any v2 score):** PAMAP2 activity labels are only approximately aligned with the movement at transitions, so edge windows can contain part of the neighbouring activity; they are outside the steady-state recognition target. The reason is label alignment, not classification difficulty. 5 s is about two window lengths and was not tuned.
- **Validation evidence (no training, `results/phase1/trim_validation.md`):** no client x class pair lost; 93-95% of windows kept; retained-window covariates unchanged (MMD^2 0.038 v1 vs v2, below the 0.071 sampling reference of the blocked train/test control).
- **Reporting:** v2 is the primary protocol for all Phase 2+ experiments. The frozen v1 results (tag `phase1-frozen`) are reported as a sensitivity analysis. All methods use the same protocol. If the v1 vs v2 method ranking changes, this is reported.


### Amendment A2 - 2026-10-27 (Phase 2 drift benchmark definition, before any detector or adaptation experiment)
- **Stream:** 60 rounds; drift starts at round 20 (S1 sudden, S3 recurring: fixed or +-5 random per client; S2 gradual: asynchronous onsets 20-30, 10-round ramp). S3 recurring: on 10 rounds out of every 20.
- **Pools:** train = clean pre-drift data; val = arrival stream (windows arrive in randomised-block order, drift applied per round; this is what detectors monitor and adaptation may use); test = held-out evaluation pool, transformed at each round's strength. The primary endpoint (Section 2) is therefore measured on unseen post-drift test windows.
- **Coverage:** partial = 3 of 8 clients (chosen by seeded draw), full = 8 of 8.
- **Scenario S4 added** (feature-level drift: one sensor only) so that all four types of the type classifier have ground truth. S0-S3 as planned.
- **Severity (3 levels per transform)** is ordinal within a transform and not comparable across transforms. Levels were calibrated once on **tuning seed 1001** (`results/phase2/severity_check.md`), changing only the rotation levels (initially 15/30/60 deg collapsed the model, now 10/20/30). Evaluation seeds were not used for calibration.
- Confirmatory comparisons use the `med` severity of each variant; low and high are reported as a sweep.

### Amendment A3 - 2026-10-27 (Phase 3 detector and drift-type protocol, registered before any detector was run)
- **Seeds:** Phase 3 uses ONLY tuning-side seeds. Detector hyper-parameters are tuned on seeds 1001-1003; detector validation and the drift-type classifier use seeds 1004-1010 (leave-one-seed-out). The 10 evaluation seeds (42, 123, 999, 2024, 7, 11, 13, 17, 19, 23) are not touched until Phase 6.
- **Monitored model:** one frozen local LSTM per client (E1 recipe, v2 protocol, 60 epochs) per seed. The detectors are evaluated on its per-window outputs for the arrival stream (Phase 2 `val` pool). Phase 4 repeats the key measurements with the FL-deployed model.
- **Signals (per arrival window):** error bit (label-dependent), prediction entropy (label-free), window statistics (mean, std, std of first difference per channel; label-free, model-free).
- **Detectors (equal tuning effort, small fixed grids):** D1 ADWIN on error; D2 Page-Hinkley on error; D3 Page-Hinkley on entropy; D4 MMD (window statistics vs a reference drawn from the clean train pool, threshold from the null of train-vs-train draws); D5 two-level: stage A label-free trigger (D3 or D4 or a 10%-label sentinel ADWIN) + stage B supervised confirmation on the next L labelled windows, with cooldown. Label cost (labelled windows used) is reported for every detector.
- **Matching rules (fixed):** ground truth = manifest onsets. TP = first alarm in [onset, onset + 20 rounds). Delay = alarm window - onset window (also in rounds). Miss = no alarm in that horizon. FALSE alarm = an alarm raised while drift strength alpha = 0. Alarms while drift is active but outside a first detection are reported as redundant, not false.
- **False-alarm bound (agreed before tuning):** <= 1 false alarm per 1,000 clean windows, checked on S0 streams and on the pre-onset part of drifted streams. Each detector is tuned to minimise mean delay (misses count as the full horizon) subject to the bound on the tuning seeds, then the bound is re-checked on seeds 1004-1010.
- **Drift types:** 4-way ground truth from the manifest (`type4`). A recurring event's FIRST onset is information-theoretically indistinguishable from a sudden drift at the time of the alarm; it is reported separately (`recurring_first`) and excluded from the identifiable 4-way accuracy, which includes recurring re-occurrences (typed using a memory of earlier episodes). Rule-based and learned (logistic regression / gradient boosting) classifiers are compared by leave-one-seed-out accuracy, per-class recall, confusion matrix and a majority-class baseline. Classification uses a fixed look-ahead of 5 rounds after the alarm (the typing delay is reported).
- **Real drift** changes no input statistics, so label-free detectors cannot see it by construction; this is reported, not hidden. The sentinel (10% labels) in stage A and the supervised detectors are the only ones that can.
